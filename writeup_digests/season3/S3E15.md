- **TL;DR:** Tree-based iterative imputation + author-keyed value clipping feeding a deliberately diverse blend;
  the winner is the blend, not the best single model.
- **Architecture:** CASCADE · stages=2 · l1=not stated (families named: tree-based, NN, linear, nearest-neighbours) ·
  l2=none stated (blend weights/algorithm never published) · novel=none · mod=multitarget ·

### S3E15-03 · 3rd · alexdippolito (Alex D'Ippolito) · LB 0.07555 (public, tuned model)/not stated · CV 0.07305 (untuned XGBoost), ~0.0732 (leakage-free workflow)

- **TL;DR:** Hand-written author-conditioned fills, then a KNN imputer (n_neighbors 87-89) for the rest, feeding 4 GBMs blended with

- **Architecture:** CASCADE · stages=2 · l1=4 (3 LightGBM + 1 XGBoost) · l2=none (4 hand-set weights) · novel=none ·
  mod=multitarget,multi-view ·
  topo=manual per-author rules → KNNImputer [remaining columns] → 4 models (each a different feature view) → 4-weight blend
  - Stage 1 is imputation whose outputs are the stage-2 features (impute-then-predict forward flow); it is itself a decomposition —
    `D_e`, `D_h`, `length`, `pressure`, `mass_flux` are filled column by column, hand rules first, then one KNN pass for the leftovers.

    (model 2 = model 1 + 2 engineered columns; model 3 = model 2 + a PLS component).

- Structural quirk exploited: the synthetic competition rows are noisier copies of the original dataset, so original data must never enter the
  validation rows, but helps enormously appended to training folds and as the lookup source for imputation.
- Target leakage is a *priced tradeoff*, not a bug: the KNN imputer uses the target column, so pre-CV imputation leaks slightly while
  raising input accuracy.
- **Features:** manual pattern fills, verbatim code for author 'Inasaka' rows:
  - `data.loc[(data['author'] == 'Inasaka') & ((data['D_h'] == 3.0) | (data['length'] == 100.0)) & (data['D_e'].isnull()), 'D_e'] = 3`

## S3E15 — consensus recipe
- **Architecture distribution:** 1st `CASCADE` (iterative tree imputer per missing column → diverse pool → ensemble, blend weights unpublished) ·
  2nd `CASCADE` (original-dataset pair/triplet + MICE imputers → LGBM + XGB ensemble, no meta) ·
  3rd `CASCADE` (manual per-column rules → KNNImputer n=87-89 → 4 GBMs, 4 basic weights) ·
  5th `STACK2` (rule-based imputation → multi-view models → Ridge with intercept and negative coefficients) ·
  6th `STACK2` (per-member LGBMImputer/IterativeImputer → 5 LGBMs → LinearRegression, no intercept) ·
  9th `AUTOML` (5 AutoGluon runs, IterativeImputer+DTR and 2-stage pseudo labels upstream, weighted ensemble) ·
  11th `AUTOML` (mljar + AutoGluon on fillna-only preprocessing) · 14th `FLAT` (hillclimbers weight search with negative weights over
  publicly-preprocessed members).
  - **winner topology: `CASCADE`** — a fitted imputer stage feeding a diverse predictor blend; all three medalists are
    impute-then-predict chains, and the two entries with a trained meta-learner (5th, 6th) finished below all three.
  - Read-across: the only `FLAT` entry (14th) published the best private numbers in the set (0.072741 submitted, 0.072698 unselected),
    so the meta-learner complexity bought no measurable rank over a disciplined blend.
- **New architectures at the board:** one — `FT-Transformer`, as an AutoGluon member inside 9th's weighted ensemble (S3E15-09);
  it is not the winner and no score is published for it.
  - `novel=none` for 1st, 2nd, 3rd, 5th, 6th, 11th, 14th: the board is stock GBM (LightGBM/XGBoost/CatBoost), linear models, NN members
    unnamed, and the vendor stacks AutoGluon (9th, 11th) and mljar (11th); 2nd's baselines ran on FLAML and Optuna tuning, not AutoGluon.
  - An auto-encoder appeared at 1st only as a rejected experiment ("didn't seem to add much"), never as a submitted component.
  - No TabM/NODE/TabPFN/Trompt-family architecture appears anywhere in this set.
- **Agreed on (6 of 8 — S3E15-01, S3E15-02, S3E15-03, S3E15-05, S3E15-06, S3E15-11):** the `author` / `geometry` / `D_e` / `D_h` uniqueness
  relations are the imputation oracle. 1st clips other features once `author` is known; 2nd matches unique pairs and triplets from the original
  dataset; 3rd hard-codes them per author ('Inasaka' rules); 5th derives all seven rules from `groupby`; 6th fills `geometry` from `author`

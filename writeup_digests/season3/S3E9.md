### S3E9-23 · 23rd · slythe (Andrew Schleiss) · LB not stated/not stated · CV linear models ~14 RMSE -> ~12 RMSE (only figure given; no absolute final score)

- **Link:** https://www.kaggle.com/c/playground-series-s3e9/discussion/394600
- **Status:** FETCHED (1 attempt; 8,056 B incl. 4 comments) — rank discrepancy resolved from the page metadata: the page's official writeup badge reads "Solution Writeup · 23rd place" while the author's title ("#12th place solutions"), the citation slug, and commenter Tariq Mahmood all say 12th; the official badge wins, entry stays `S3E9-23`.
- **TL;DR:** A reusable 6-notebook pipeline (EDA -> feature creation -> selection -> single-model tuning -> multi-model CV -> ensembling); the standout is a per-column duplicate group-mean feature that fixed his linear models.
- Like 1st, he rejects Optuna ("tends to overfit") and tunes manually.
- **Architecture:** FLAT · stages=1 · l1=many tuned models (only linear models are named on the page; no other family stated) · l2=none (scipy-optimize blend weights; linear calibration is post-processing) · novel=none · mod=gp ·
  topo=EDA -> gplearn symbolic-transform FE -> RFECV/manual RFE -> manual single-model tuning -> nested + best-fold CV (save OOF+test preds) -> scipy-optimize weighted blend + linear calibration
  - Ensembling finds blend weights over saved validation+test predictions with `scipy.optimize` (a weight search -> `FLAT` per ruling 1, not a meta-learner on the OOF matrix).
  - `mod=gp` = gplearn Symbolic Regression Transformation used as a feature generator (he reports it underperformed this episode).
- **Setup:** duplicates exploited — group the trainset's duplicated rows by each column and take the mean target per group, then bin each feature onto those group means as new features. Metric RMSE (lower-better). Nested CV and best-in-fold CV both run; validation (OOF) predictions optimised rather than training predictions (the best-fold notebook has to use training predictions).
- **Features:** `Additional_Features`: loops over the test columns (dropping `is_generated`); for train rows that are duplicated (ignoring the target), `grp_target = df_trn[df_trn.drop(target, axis=1).duplicated()].groupby(col).mean()[target]`, bins built from `grp_target.index` (with a 0 or max+1 edge), then `df[f"{col}_grp_mean"] = pd.cut(df[col], bins, labels=grp_target.values)` cast to float and filled with 0 — applied to both train and test. Also gplearn Symbolic Regression Transform (weak this episode, strong in ep 5) and RFECV + manual recursive feature elimination. Additional features lifted from other top notebooks did NOT improve his CV.
- **Models:** many tuned models ensembled; linear models called out explicitly (the group-mean feature moved them from ~14 to ~12 RMSE); other families and all hyperparameters are not stated on the page (the 6 notebooks are the record). Manual tuning, not Optuna.
- **CV:** nested CV + best-in-fold CV across all models; validation and test predictions saved for the ensemble stage. Splitter type, fold count, seeds: not stated numerically.
- **Ensembling:** step 6 applies ensembling to the saved test+validation predictions; `scipy.optimize` for blend weights and linear models for calibration; weights and member count not stated numerically.
- **Post-processing:** "calibration using linear models" applied to the blended output — a post-prediction calibration step (ruling 2), not a training stage.
- **Gains:** (-2 RMSE, his biggest) per-column duplicate group-mean feature moved the linear models from ~14 to ~12 RMSE. Unquantified: RFECV + nested/best-fold CV for model selection. (No absolute final CV or LB number published.)
- **Failed:** gplearn Symbolic Regression Transformation — "it actually didn't work that well this episode (it did well in episode 5)". Extra features copied from other top notebooks — did not improve his CV (he doubts he was right to skip them). Optuna — "tends to overfit", so he tunes manually.

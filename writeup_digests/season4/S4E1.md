### S4E1-02 · 2nd · lukaszl (lukaszl) · LB not stated/0.90462 (private) · CV not stated

- **Link:** https://www.kaggle.com/c/playground-series-s4e1/discussion/472496
- **Status:** FETCHED (`/c/` form worked first try; body + 40 comments)
- **TL;DR:** One idea, zero domain modeling: ~1000 binary features marking whether each feature-subset of a synthetic row appears unchanged in the ORIGINAL dataset, then LGBM + AutoGluon averaged.
- **Architecture:** FLAT · stages=1 · l1=2 (LGBM on 50 GA-selected features; AutoGluon on all) · l2=none (fixed (a+b)/2 average) · novel=none · mod=gp ·
  topo=original-dataset row matching → ~1000 subset-membership flags + 10 base cols → {LGBM[50 feats via genetic algo], AutoGluon[all, best_quality, 4h]} → 50/50 average → + paddykb leakage post-processing
  - The blend is deliberately trivial — the entire solution is the feature construction; AutoGluon is one member of a 2-way average, so per ruling 6 not `AUTOML`.
  - `mod=gp`: a simple genetic algorithm run "for a few hours" selected the 50-feature subset for LGBM (author comment reply) — feature/selection search, not a meta-learner.
  - The paddykb "Feeling lucky trick" is a leakage-based correction applied to the final predictions (worth +0.01 to his result), i.e. Post-processing per ruling 2.
- **Setup:** binary classification on `Exited`; overall target rate 0.21; ~3600 teams (stated by 3rd's page, not his); rows/cols/slots: not stated on this page. Structural quirk exploited: the generator could not preserve the target distribution across feature-combination levels — his features monetize that.
- **Features:** for EVERY subset of size 1,2,3…10 of ['CreditScore','Geography','Gender','Age','Tenure','NumOfProducts','HasCrCard','IsActiveMember','EstimatedSalary','Balance']: feature = 1 if that exact subset of values appears unchanged in the original dataset, else 0 → ~1000 binary flags; plus the subset [CustomerId, Surname] as one more flag.
  - Why it works, author's own numbers: target rate on the whole dataset 0.21; for ['CreditScore','Geography','Balance'] membership: False → 0.171026, True → 0.269552; for ['CreditScore','Gender','NumOfProducts']: False → 0.203034, True → 0.707857.
  - A "latest submission" additionally included some publicly available features — "they didn't change much" (no public-OOF/prediction files entered the pool, so no `public-oof` tag is claimed).
- **Models:** LGBM on 50 selected features (subset includes base features), "without excessive hyperparameters tuning" — params not published; AutoGluon with ALL features, `presets='best_quality'`, `time_limit=14400`, nothing excluded (author comment reply).
  - Private LB per member: LGBM 0.90203, AutoGluon 0.90378, (lgbm+autogluon)/2 = 0.90462 (final).
  - Seeds, fold counts: not stated.
- **CV:** no CV at all published — validation was done by the original-dataset membership itself ("checking whether it appears unchanged"); CV-vs-LB gap not computable. Author's implicit trust model: the leakage features ARE the signal.
- **Ensembling:** plain arithmetic mean of the two members' predictions; no weights fitted.
- **Post-processing:** @paddykb "Feeling lucky trick" — he states "+0.01 to the result, a little bit less than 0.02" (implying others got more from it) and attributes the smaller lift to his features already "partially explain[ing] this 'strange' behavior of the dataset".

### S4E1-03 · 3rd · iqbalsyahakbar (Iqbal Syah Akbar) · LB not stated · CV >0.902 (the three CatBoosts; 30-fold submission runs)

- **Link:** https://www.kaggle.com/c/playground-series-s4e1/discussion/472413
- **Status:** FETCHED (`/c/` form; body + 48 comments)
- **TL;DR:** Encoding as architecture: 12 CatBoost-style target encodings over cast-integer columns and SVD components, 7 pipeline-disciplined models, Ridge-defined blend weights, 30 folds for submission.
- **Architecture:** STACK2 · stages=2 · l1=7 (LogisticRegression, MLP (NN, framework not stated), XGBoost, LightGBM, 3× CatBoost by bootstrap type) · l2=Ridge Classifier defining the blend weights (a model fitted on OOF predictions per the body) · novel=none · mod=multi-view ·
  topo=TF-IDF+SVD + AllCat + ZeroBalance + int-cast Salary/Age → per-model encoding branches (CatBoostEncoder / MEstimate / built-in) → 7 model OOFs → Ridge-weighted blend → paddykb leakage post-processing
  - `multi-view` is load-bearing: each branch sees different encodings (LR/NN share one encoding scheme, XGB/LGB mix CatBoostEncoder + MEstimateEncoder, CatBoost trio uses its built-in encoder + vectorization on 2 features).
  - LR is explicitly a probe, not a contender ("lowest performing model but greatest for experimenting which features to encode").
  - Fold count is a stage-level knob here, not just hygiene: 5 folds to experiment, 30 folds (≈12 h) to submit, because averaging 30 differently-bootstrapped subsets acts like dataset enlargement.
- **Setup:** binary churn; ~3600 teams; 3rd after 11 months of trying; rows/cols not stated. Structural quirks exploited: (1) original-data rows concatenated BEFORE competition rows so order-dependent CatBoostEncoder sees the original first; (2) concatenating the original dataset TWICE gave his best private score; (3) paddykb leakage post-processing.
- **Features:** TF-IDF vectorization + TruncatedSVD as a reusable pipeline class (credit @arunklenin), applied with different vectorization/decomposition combos per feature set; manual features from aspillai's notebook minus scaling and `IsSenior`, with `Sun_Geo_Gend_Sal` modified = `AllCat` (concat of nearly all features planned for encoding, excluding `IsActiveMember` because `IsActive_by_CreditCard` was encoded instead); `ZeroBalance` indicator; `EstimatedSalary`×100 and `Age`×10 cast to int to make them encodable as high-cardinality categoricals (side effect: Age×10 + aspillai's binning == binning Age/2).
  - Encoded: everything except `Balance` and `HasCrCard` — 12 features; Surname SVD components (4) encoded too; permutation importance found nothing negative, dropping the weakest feature hurt → no columns dropped.
- **Models:** per branch, author's numbers: LR (weakest, encoding probe); NN Input→32→64→16→4 LeakyReLU→1 Sigmoid, AdamW, same encodings as LR, the ONLY model without vectorization; XGBoost with CatBoostEncoder + MEstimateEncoder on different feature sets, Optuna HPO, vectorization on 4 features (max 500 features, 3 components); LightGBM "somewhat similar" preprocessing; 3× CatBoost bootstrap variants (no / Bayesian / Bernoulli), vectorization on 2 features (max 1000, 4 components), all CV > 0.902, no HPO ("as slow as snail"). Other hyperparameters/seeds: not stated.
- **CV:** stratified folds, 5 for experiments, 30 for the submission (~12 h runtime); all preprocessing INSIDE sklearn pipelines "because I'm a freak when it comes to leakage prevention in cross-validation"; CV-vs-LB: he observed more folds ⇒ better score, and original-data double-concat best on private (LB-vs-CV direction, no paired numbers); CatBoost trio >0.902 CV.
- Trust verdict: CV-driven end-to-end; permutation importance and drop-tests used instead of domain knowledge ("this competition uses synthetic dataset. Domain knowledge doesn't matter much", comment reply).
- **Ensembling:** 7 OOF prediction sets; blend weights "defined with Ridge Classifier"; no weights published; 30-fold averaging across folds acts as the within-model ensemble.
- **Post-processing:** "postprocessing related to the data leakage by @paddykb" — the same community trick as 2nd; mechanism named but not detailed on the page.
- **Gains:** (stated, no number) increasing folds 5 → 30 at submission time — his first-listed score-boost note ("one way to boost the score from what I have noticed"), magnitude not published.
  - (stated direction, no number) original dataset concatenated TWICE and placed FIRST for encoder ordering; encoding Salary/Age as cast-int categoricals; Age×10 binning side effect.
  - (stated) TF-IDF+SVD components also fed to encoders — "you can encode them too".
  - No metric deltas published for individual features or models.
- **Failed:** dropping any feature (permutation importance never negative; removing the lowest-importance one lost performance); scaling and `IsSenior` from aspillai's recipe (deliberately not included — implied dead ends); no negatives listed for the models themselves since LR was kept as a tool not a member scorer.
- **Comments:** 48 comments (4 appreciation) counted on this page; substantial author replies mined:
  - Why XGB/LGBM dislike category-encoders' CatBoostEncoder: it underfits low-cardinality (<100 unique) categoricals; this comp was "a bizarre exception"; CatBoost's own built-in encoder behaves differently (reply to @thiagomantuani).
  - Why more folds help: 30 subsets ≈ artificially enlarged dataset whose members the blender treats differently; his stated "last resort" when CV ideas run out (reply to @Akira / stellarhymia, 237th).
  - Kaggle workflow tip: "Save Version" instead of draft-run to survive the 12 h notebook limit overnight (reply to @jordirosell, 287th).
  - Commenter @gunhyunjeong (35th) used 20 folds, @chayanonc (241st) 10; commenter @Aravind Pillai (aspillai, 11th — the feature donor) congratulates; 2nd place @lukaszl congratulates.

## S4E1 — consensus recipe
- **Architecture distribution:** 2nd `FLAT` (LGBM + AutoGluon 50/50 average over ~1000 generator-forensics features) · 3rd `STACK2` (7 pipeline-disciplined models, Ridge-fitted weights, 30-fold) · 17th `FLAT` (AutoGluon 3-level stack + prior models + public notebooks averaged at submission level; mod=public-oof) · **best documented topology (no 1st writeup exists): `FLAT` at 2nd** — two of three blend at submission level, the only fitted meta-learner (Ridge) sits at 3rd.
- **New architectures at the board:** none submitted — all three `novel=none`; `TabPFN` appeared at 17th only as a screened-out architecture (listed in "what doesn't work"). The NN at 3rd is a stock LeakyReLU MLP. The genuinely new element in this competition is not a model but a feature type: exact-subset membership flags against the original dataset (2nd).
- **Agreed on (3 of 3 — S4E1-02, -03, -17):** crediting @paddykb — 2nd adds the named "Feeling lucky trick" (+0.01 to his result), 3rd applies "postprocessing related to the data leakage by paddykb", 17th lists "Ideas published by @paddykb" among what worked (leakage itself named on only 2 of 3 — S4E1-02, -03).
- **Agreed on (2 of 3 — S4E1-02, S4E1-03):** the ORIGINAL dataset is signal when consumed correctly — as row/encoder-order structure (2nd matches rows against it; 3rd concatenates it BEFORE competition data, and twice for his best private). 17th tried plain inclusion and lists "Original dataset" as failed — the disagreement is about HOW, not whether it touches the data.
- **Agreed on (2 of 3 — S4E1-02, S4E1-17):** AutoGluon inside the submitted solution — as a blend member at 2nd (`best_quality`, time_limit=14400, nothing excluded) and as the 3-level "Frankenstein II" stack at 17th; 3rd uses no AutoGluon at all (his hand-built 7-model stack plays the equivalent role).
- **Agreed on (2 of 3 — S4E1-03, S4E1-17):** feature factory + hard pruning as the pipeline spine (3rd: TF-IDF/SVD + AllCat + 12 encodings; 17th: OpenFE 470 → BorutaSHAP/RFECV 103); 2nd needed no pruning because his GA chose the 50 (comment reply).
- **Divergences:** validation philosophy is inverted: 3rd runs obsessive leak-proof pipelines, 5→30 folds, and CV ≈ 0.902 per CatBoost; 2nd publishes NO CV at all and lets leakage features + LB decide; 17th's stack CV (0.898947) sits +0.0026 ABOVE its private (0.89637) — the three entries cannot agree on whether local validation ranks submissions on this dataset.
- Divergence on blend sophistication: 3rd fitted Ridge weights over 7 encodable views; 2nd averaged 2 members 50/50; 17th averaged two last-hour collections — and the published private scores line up 0.90462 (2nd) > 0.90106 (17th) — the SIMPLEST blend (2nd) wins among the documented entries, so extra stacking bought rank elsewhere, not here.
- **Highest-leverage single trick:** the generator-forensics features and the leakage trick, one per side of the leaderboard: 2nd's subset-membership flags turned the synthetic-data process itself into ~1000 predictive binaries (e.g. target rate 0.707857 vs 0.203034 for one 3-column subset match); 3rd's fold-count lever (5 → 30) is his first-listed stated boost (no number published), and @paddykb is credited by all three (the leakage trick named explicitly only at 2nd and 3rd).
- **Nothing worked:** dropping features on synthetic data — permutation importance never negative at 3rd; PCA/ICA, standalone boosting submissions, TabPFN and surname features at 17th; adding public-notebook features at 2nd ("didn't change much"); naive original-data concatenation at 17th; and any real-life portability of the whole family of leakage solutions (2nd's own punchline: "do not ask the client for the original dataset").

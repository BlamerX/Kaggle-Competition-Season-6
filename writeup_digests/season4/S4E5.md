### S4E5-01 · 1st · adaubas (display name "aldparis") · LB 0.86943 public/not stated · CV not stated numerically (Ridge ensemble judged by CV, values never printed)

- **TL;DR:** A Ridge ensemble (`positive=False`, `fit_intercept=False`) fitted on 3-repeated-KFold OOF columns from 30+
  self-built GBMs plus 6 AutoGluon OOF files; row-sum physics discovered by EDA.
- **Architecture:** STACK2 · stages=2 · l1=30+ own GBMs (CatBoost/XGBoost/LightGBM, many feature subsets) + 2 public
  notebook members + 6 AutoGluon OOF sets · l2=Ridge (positive=False, fit_intercept=False), columns chosen by CV ·
  novel=none · mod=public-oof,multi-view ·
  topo=row-sum/sorted/count/TE features -> 30+ GBMs x 3 repeated kfold + AutoGluon OOF [6 files] -> Ridge matrix fit
  (columns CV-selected) -> submit
  - A meta-learner (Ridge) is fitted on the OOF matrix, so this is `STACK2` and not `FLAT` (ruling 1).
  - Ruling 6: AutoGluon supplies level-1 prediction columns; the submitted topology is his own Ridge, so not `AUTOML`.
  - Ruling 3: the public OOF/prediction sets add members (counted in `l1`), not a third stage.
  - `multi-view` is stated on the page: the 30+ GBMs were trained "with various sets of features: sometimes with sorted
    original features, or sometimes with count features ... sometimes with target encoder, sometimes without".
  - The winning prediction is the stack, not any single model: he names "final parsimonious ridge regression, many GBM, and
    AutoGluon (close to the top)" as the combination (author comment).
- **Setup:** 17 original features + target `FloodProbability` (implied by his "sum of 16 of 17 orginal features" statement);
  row/col counts not stated.
- Only 2 submissions after 18 May ("I'm proud to have made only 2 submissions between the 18th of may and the end");
  submission slots not otherwise stated.
- Structural quirk exploited: the columns are Poisson-like, so a row sum is a near-sufficient statistic — and the original
  dataset is "completly different" from the synthetic train set.
- **Features:** row statistics and quantized-value physics, all on `test.columns` (the 17 original features):
  - useful, published: `sum` of each row (`train["sum"] = train[test.columns].sum(axis=1)`), `std` of each row, `max` of each row,
    sorted original features along the row axis (credits @siukeitin, discussion 499579 "Sorting along the feature axis as
    feature engineering"), and count features for the number of variables with a value higher than 6, 7, or 8.
  - count feature names as printed: `"nb_inf4"`, `"nb_inf3"`, `"nb_inf2"`, `"nb_sup6"`, `"nb_sup7"`, `"nb_sup8"`.
  - "magic feature" = a target encoder on the row sum, since the target behaves like a discrete variable:
    `train.groupby("sum")["FloodProbability"].std()`.
  - most important feature credited to @ambrosm (no name given on the page).
  - useless and dropped: the original features themselves for his GBMs, per-row skewness, per-row kurtosis, redundant features.
  - Selection method: permutation feature importance (scikit-learn implementation) plus a backward elimination technique.
  - Target transformation variants used by some models (credited to @act18l, discussion 499263#2787165):
    `target_transf = FloodProbability - df[original_features].mean(axis=1) * 0.1` and
    `target_transf = (FloodProbability*400 - train[original_features].mean(axis=1) * 40).astype(np.int16)` — the split is
    "strong signal (sum)" vs "noisy signal (deviance from sum)".
- **Models:** "more than 30 GBM's", families CatBoost, XGBoost, LightGBM, each retrained on different feature sets (with/without
  sorted features, with/without count features, with/without the target encoder, with/without the target transformation).
- First 10 days: default parameters only, with early stopping, no HPO at all — time spent on features and the ensemble loop.
- Optuna afterwards, on Kaggle GPU quota only, `max timeout = 5400 seconds` per study, and only these parameters tuned:
  - `depth` for CatBoost and XGBoost; `num_leaves` for LightGBM; `alpha`, `lambda`, `min_child_weight`/`min_child_samples`
    for XGBoost and LightGBM; `bagging_temperature`, `random_strength` for CatBoost; `subsample`, `colsample_by_node`
    (printed as such) for XGBoost and LightGBM.
- Deliberate diversity: default `grow_policy` of each GBM kept, because "xgboost, catboost and lightgbm have each a different
  default grow_policy value, it gives variety of predictions"; `learning_rate` default or 0.1; `n_iterations` set by
  early stopping (`od_wait` in CatBoost).
- AutoGluon members: the public `autogluon-starter` by @mfmfmf3 (used as a blind blend output first, then as OOF), then "3 oofs

- Second public member notebook: `Flood Prediction LGBM` by @igorvolianiuk.
- Seeds, per-model hyperparameter values, library versions: not stated.
- **CV:** all models trained on 3 repeated k-fold (K not stated); the ensemble's columns were selected "by CV".
- Published public-LB ladder with the matching modelling step: `0.86939` (blind blend of AutoGluon output, end of week 2) ->
  `0.86941` (properly fitted ensemble after receiving a complete AutoGluon OOF file, end of week 3) -> `0.86943` (final

## S4E5 — consensus recipe
- **Architecture distribution:** 1st `STACK2` (30+ GBM OOF + 6 AutoGluon OOF columns -> Ridge, `positive=False`,
  `fit_intercept=False`) · 2nd `STACKN` (56 models -> LR-fitted subset blends reused as columns -> LR + Forward Feature
  Selection -> fixed 0.6/0.4 blend with a teammate's stack) · 4th `FLAT` (many models, 3 feature sets -> hill-climbing weights).
  - **winner topology: `STACK2`** — the cheapest stack on the board beat the 3-level one (2nd) by an unpublished private
    margin and beat the 1-level flat blend (4th) on rank.
  - Read-across: all three top documented entries are "lots of tree models + one blender"; the only structural difference is
    whether the blender is fitted (1st, 2nd) or searched (4th), and whether AutoGluon OOF is inside the matrix (1st yes,
    2nd no, 4th not stated).
- **New architectures at the board:** none won.
  - 2nd is the only entrant with non-stock models: `NGBoost` (`ngb`, weight -0.011743), `Linear-Tree`,
    `Linear-Forest-Regression`, `Linear-Boosting-Regression` — all untuned, "small contribution overall"; plus `PyBoost`
    inside his teammate's branch.
  - `AutoGluon` is the recurring vendor architecture: 6 OOF files as level-1 columns for 1st (ruling 6, so the tag stays
    `STACK2`), two public AutoGluon solutions inside 2nd's partner branch, and never as the submitted topology for anyone
    documented here.
  - 4th: `novel=none` — tree models plus DecisionTreeRegressor ensembles only.
- **Agreed on (3 of 3 — S4E5-01, S4E5-02, S4E5-04):** pool width is the strategy, because the task is near-noise-limited.
  - 1st "I trained more than 30 GBM's"; 2nd "Our solution contained of total of 56 (excluding autogluon)"; 4th "The crucial
    strategy for this competition was to blend as many models as possible... we were essentially predicting noise".
- **Agreed on (3 of 3 — S4E5-01, S4E5-02, S4E5-04):** borrowed public work is load-bearing, at the hyperparameter or the
  prediction level.
  - 1st: @mfmfmf3's AutoGluon starter + @igorvolianiuk's LGBM notebook + @siukeitin's sorted-features idea + @ambrosm's
    top feature + @act18l's target transform.
  - 2nd: 4 named notebooks supplying hyperparameters, @ambrosm/@siukeitin features, the Team Oxygen AutoML 2nd-place notebook,
    @mfmfmf3/@meloncc AutoGluon solutions.
  - 4th: the row value-count feature comes from the AutoML Grand Prix 1st-place write-up, and his blender is his own public package.
- **Agreed on (2 of 3 — S4E5-01, S4E5-04):** row-wise aggregates of the original feature block are the core FE — both publish
  row statistics plus a count feature. S4E5-02 credits @ambrosm and @siukeitin for its features but prints no name or formula,
  so it is not counted.
  - The count primitives differ and must not be merged: 1st counts variables whose value exceeds a threshold
    (`nb_sup6`, `nb_sup7`, `nb_sup8`, plus `nb_inf4/3/2`), 4th counts the occurrences of each unique value in a row (taken from
    the AutoML Grand Prix 1st-place write-up). 1st adds the sorted-feature row (`@siukeitin`); 4th names no sorted feature.
  - Split worth noting: 1st DROPs the original features, skewness and kurtosis as useless after permutation importance, while

- **Agreed on (2 of 3 — S4E5-01, S4E5-04):** Optuna for hyperparameters (1st on Kaggle GPU quota, 5400 s max per study, only
  depth/num_leaves/regularizers/bagging/sampling tuned; 4th "some manually tuned and others optimized using Optuna").
  S4E5-02 says "fine tuned with different combination of `grow_policy`, `tree_method`, `objective`, `sampling_method`" but
  never names a tuner, so it is not counted.
- **Divergences:** the blender is contested at the 0.00001-0.0001 R2 scale, and the ranking does not follow the choice.
  - 1st moved from `LinearRegression(positive=True)` to `Ridge(positive=False)` and calls it "a little improvement".
  - 4th moved from Lasso/Ridge to hill climbing and calls that the best result.
  - 2nd keeps `LinearRegression()` but adds subset re-blending + Forward Feature Selection.
  - Tilii (3rd, not documented in this index) explicitly disputes that Ridge mattered at all: "I don't think it was Ridge or

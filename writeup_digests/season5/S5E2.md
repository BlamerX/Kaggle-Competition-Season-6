- **Setup:** rows/cols/slots not stated on this page. Structural quirk exploited: "weird and unnatural" data (his
  weird-data discussion/564056 — elaborated there, not on this page: the 4M-row synthetic train is ~80 copies of each
  original row, so duplication-finding features like groupbys/KNN carry the signal). On this page itself the quirk is
  used via `Weight Capacity (kg)` — "the most powerful column" — whose float digits are extracted "as in a product ID"
  and which is rounded into bins.
- **Features:** the winning asset (~500 final features; 138 in the public simplified build). Named families, with his formulas:
  - `Groupby(COL1)[COL2].agg(STAT)` for STAT in mean/std/count/min/max/nunique/skew — nested folds used whenever COL2 is the target.
  - `Groupby(COL1)['Price'].agg(HISTOGRAM BINS)` — per-group histogram bucket counts returned as features; bucket count treated as a hyperparameter (self-credited as a new idea: "I have never seen it being used before").
  - `Groupby(COL1)['Price'].agg(QUANTILES)` with `QUANTILES=[5,10,40,45,55,60,90,95]` → 8 columns per group key.
  - All-NaN bitmask column: `train["NaNs"] += train[c].isna()*2**i` over the categorical columns (base-2 pattern of missingness), itself usable as a groupby key.
  - Rounded-bin copies of the strongest column: `for k in range(7,10): train[f"round{k}"] = train["Weight Capacity (kg)"].round(k)`.
  - Float-digit extraction (idea credited to @jordanbarker in discussion/563743): `digit{k} = ((WC*10**k) % 10)` for k=1..9, `int8`, fill −1.
  - All 28 pairwise categorical combinations from 8 categoricals via integer packing: `((c1+1 + (c2+1)/(m2+1))*(m2+1)).astype("int8")` with label-encoded values, −1 = NaN.
  - Original-dataset MSRP join: `orig.groupby("Weight Capacity (kg)").Price.mean()` merged as `orig_price` — rationale:
    original data = manufacturer suggested retail, competition data = store prices.
  - Division features over groupby stats: `TE1_wc_count_per_nunique = TE1_wc_count/TE1_wc_nunique`, `TE1_wc_std_per_count = TE1_wc_std/TE1_wc_count`.
  - `Weight Capacity (kg)` is called the most powerful column; most families key off it.

## S5E2 — consensus recipe
- **Architecture distribution:** 1st `SINGLE` (one XGBoost on ~500 FE features) · 2nd `STACKN` (69 L1 → 35 NN stackers →
  Ridge, 100-model submission, stages=3) · 3rd `STACK2` (4 trees → BayesianRidge, plus a public-submission tail blend).
  - **winner topology: `SINGLE`** — and the score evidence points the same way: 2nd's full 3-level stack only beat its
    own best single L1 by −0.01769 CV and still finished behind 1st's lone XGBoost; 1st's own words: "a single model
    with creative feature engineering wins this competition".
- **New architectures at the board:** none tagged `novel=` — every entrant is stock GBM/NN/linear. Closest calls: 3rd's
  supervised autoencoder (reconstruct + predict dual branch, latent→GBM) and 2nd's public autoencoder + MLP stackers;
  both are feature/meta components, not new tabular architectures, and no one submitted an autoencoder/NN as the model.
- **Agreed on (3 of 3 — S5E2-01, S5E2-02, S5E2-03):** `Weight Capacity (kg)` is the load-bearing column and must be
  multiplied: 1st rounds/digitizes/histograms it into bins and keys groupbys on it; 2nd pins WeightCapacity(float)+string
  twin into every model's common top-50; 3rd builds COMBO columns `Brand*100 + Weight Capacity` and groups on it.
- **Agreed on (3 of 3 — S5E2-01, S5E2-02, S5E2-03):** target/groupby aggregation encodings as the core FE; explicit
  leakage control is stated by 2 of 3 only (S5E2-01, S5E2-02 — 1st nested folds for target-column aggregates, 2nd CuML
  TargetEncoder k-fold, explained in his comment; 3rd applies cuml smoothed TE without stating any leakage control);
  aggregators converge on mean/std/count/min/max/median(/nunique/skew) — 2nd adds that variance/std TE variants failed.
- **Agreed on (3 of 3 — S5E2-01, S5E2-02, S5E2-03):** use the ORIGINAL dataset as FEATURES only, never as appended rows
  — 1st's `orig_price` MSRP
  join, 2nd's kernel-derived original features (appending as rows: "What did not work"), 3rd's external-dataset price
  statistics (orig_price_mean/std/min/max/median + missing flag).
- **Agreed on (2 of 3 — S5E2-02, S5E2-03):** autoencoder latent features feeding the GBMs (2nd uses a public AE model +
  AE-driven tree variants; 3rd trains his own supervised AE). 1st never mentions AEs.
- **Divergences:** model-ensemble depth: 1st submitted 1 model, 3rd a 4+1 stack, 2nd a 100-model 3-level stack — with
  2nd's stack improving on his own best single by only 0.0177 CV and still losing the comp; blend philosophy: equal/hand
  weights nowhere — both stackers trained their metas (BayesianRidge / Ridge), while the winner skipped blending entirely.
  Also 2nd's public-vs-private anomaly (38.82326 vs 38.62947, 0.19379 apart) vs 1st publishing nothing: on this board
  only CV and private agreed.
- **Highest-leverage single trick:** digit/round-binning extraction of the synthetic float (`digit{k}=((WC*10**k)%10`,
  `round(k)` for k=7..9) plus per-group histogram-bin counts as features — the quirks of THIS generator (S5E2-01);
  corroborated by 2nd's float+string-twin handling of the same column.
- **Nothing worked:** sample weights (2nd); appending original data as rows (2nd); variance/std TE aggregators (2nd);
  target-copying across duplicate train/test rows (2nd); any level-3 blender except Ridge (2nd); slow
  `category_encoder` CatBoost encoder (2nd, comment); prediction-deviation amplification once the model got good (3rd);
  last-day automatic feature-selector optimization (3rd); and trusting the public board (2nd's rounded variant: it
  improved the public score but cost +0.00092 on private, 38.62947 → 38.63039 — RMSE, higher = worse).

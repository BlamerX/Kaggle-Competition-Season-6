### S6E7-02 · 2nd · kava1 · LB not stated by author/0.95085 (per S6E7-29) · CV 0.950737 OOF balanced accuracy (0.086310 OOF LogLoss)

- **Link:** https://www.kaggle.com/c/playground-series-s6e7/writeups/2nd-place-solution
- **Status:** FETCHED (first attempt, `/competitions/` + `X-Return-Format: markdown`; page has 8 comments, 4 of them technical)
- **TL;DR:** 18 base predictors combined by an SLSQP-optimized 18x3 class-specific weight matrix, then Nelder-Mead class multipliers for
  balanced accuracy.
- Title subtitle, verbatim: "18-Base Predictor Weight Optimization & Class-Specific Multiplier Tuning".
- He publishes no leaderboard score at all; 29th's writeup states 2nd place finished on 0.95085 private.
- **Architecture:** FLAT · stages=1 · l1=18 base predictors · l2=none (54 fitted blend weights, no meta-learner model) ·
  novel=FT-Transformer,RealMLP,DCNv2 · mod=public-oof,ovo,threshold ·
  topo=18 public+own predictors [LightGBM/XGB/CatBoost/HGBC/FTT/RealMLP/DCNv2/XGB-OvR] -> full OOF -> SLSQP W in R^{18x3} simplex per class
  -> renormalized linear blend -> Nelder-Mead class multipliers -> argmax
  - Submitted prediction was the weighted linear blend of all 18 level-0 members: no OOF matrix is fed to a trained second-stage model, so
    it is `FLAT`, not `STACK2` — the author's own words: "Rather than training an additional nonlinear meta-learning stage (which risks
    overfitting out-of-fold metadata), we used a direct linear combination of the base predictions."
  - What differs from a plain average: weights are per class, not per model. W has 54 free parameters (18 models x 3 classes), each class's
    column normalized so it sums to 1 (simplex constraint), fitted to minimize OOF LogLoss; blended class scores are renormalized to valid
    probabilities before LogLoss is evaluated.
  - A second, orthogonal optimization then runs on the blend output: three class probability multipliers tuned by Nelder-Mead directly
    against balanced accuracy. This is a decision-rule change, not a re-blend — it is what converts 0.889132 into 0.950737.
- **Setup:** 690,088 OOF rows implied by the per-class support column (592,561 / 39,803 / 57,724); test rows, fold count, splitter and
  submission slots: not stated.
- Structural quirk exploited: class imbalance (85.87% majority) against a mean-recall metric, fixed at the decision layer rather than in
  training.
- No test labels and no leaderboard feedback were used for tuning: multipliers were fit on the full OOF set and applied unchanged to test.

### S6E7-04 · 4th · rickyds97 (Ricky) · LB 0.95094/0.95084 · CV 0.9506326

- **TL;DR:** One FT-Transformer family plus prior-corrected argmax; "The final solution was not a huge stack or an exotic feature factory."

- **Architecture:** SINGLE · stages=1 · l1=1 FT-Transformer family x 4 initializations x 7 folds · l2=none ·
  novel=FT-Transformer · mod=threshold ·
  topo=13 raw + 39 fold-local exact-value TE -> FT-Transformer x4 members per fold -> OOF probs + fold-averaged test probs
  -> argmax(p / class_prior) -> labels
  - The submitted prediction is one model family: 4 members inside each fold is init-averaging within a single architecture, not a second
    family. There is no meta-learner and no blend anywhere in the winning path.
  - Explicitly not a stack: "There was no cross-model stacking in the final submission. XGBoost, HistGradientBoosting, RealMLP, and
    kNN-density experiments were useful for checking ideas, but none replaced the FT-Transformer submission."

- Class shares (author's table): `at-risk` 85.87%, `fit` 5.77%, `unhealthy` 8.36%.

  really a high-cardinality category key.
- **Features:** 13 raw features + 39 multiclass exact-value target-encoding features = 52 inputs.
- Formula: for every one of the 13 input columns and every one of the 3 classes, append the training-fold estimate of P(class | exact
  value). `13 columns x 3 classes = 39 additional features`.
- Worked example given: a repeated `step_count` value gets 3 features for how often rows with that exact value were at-risk / fit /
  unhealthy.
- All 7 numeric columns get exact-value encoding, not just the categoricals — the point he calls "strange" and then justifies.
- Leakage control (3 rules): the encoder for each outer fold is fitted only on that fold's training rows; training-fold encodings are
  themselves generated out of fold; validation and test rows use only mappings learned from the training fold.
- Feature-name-level detail beyond this: no ratio, interaction, frequency or imputation features are described. Columns dropped: none
  stated.
- **Models:** FT-Transformer, 7 folds, 4 independently initialized members inside each fold.
- Author's full recipe table (verbatim values): Transformer 2 blocks, hidden size 128, 8 heads.
- Numeric embedding: PLR-lite, 24 frequencies, sigma 0.1.
- Training: 16 fixed epochs, batch size 4096. Optimizer AdamW, learning rate 0.001, cosine schedule.
- Regularization: weight decay `1e-5`, no label smoothing. Class weights: none. Early stopping: none.
- Fixed epochs instead of best-checkpoint selection, on purpose: "This keeps the outer validation fold as an honest measurement rather than
  quietly using it for model selection."
- Library / implementation: Masaya Kawamata's public FT-Transformer-v2 notebook (URL under Artifacts); seeds not stated.
- **CV:** `StratifiedKFold` 7-fold, shuffle, seed 42; per-fold repeats and additional seeds: not stated.

- OOF 0.95063 vs public 0.95094 = +0.00031; vs private 0.95084 = +0.00021. No alarming mismatch.
- Trust verdict: "align your decision rule with the metric, then trust honest out-of-fold validation over a crowded public leaderboard";
  Public LB used only as a smoke test for file format, label mapping and broad sanity.
- **Ensembling:** in-fold average of 4 independent initializations; across folds, test predictions are the fold average; OOF probabilities
  kept for the decision-rule step.
- No blend weights, no meta-learner, no shared-OOF sets in the submitted path.
- **Post-processing:** `pred = classes[(probabilities / prior).argmax(axis=1)]` with

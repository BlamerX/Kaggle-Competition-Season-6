- **TL;DR:** The title names LLMs because GPT5.4, Gemini3.1 and ClaudeOpus4.6 wrote all 600,000 lines of code and built 850 models; the submitted prediction was a genuine 4-level
  stack ending in Nvidia cuML L2-logistic regression over 150 selected base models.
- The KGMON Playbook (EDA / baselines / GPU FE / GPU hill climbing / stacking / pseudo-labeling / extra training) was the recipe the agents executed.
- **Architecture:** STACKN · stages=4 · l1=feature-extraction models (cuML KNN, PyTorch denoising autoencoder, PCA clustering, cuML target encoding; count not stated) ·
  l2=GBDT+NN trained on 5x5 nested OOF from l1 · l3=GBDT+NN (`_stk` suffix members) trained on 5x5 nested OOF from l2 ·
  l4=cuML L2-penalized Logistic Regression on l3 + l2 OOF ·
  novel=RealMLP,TabM,TabICL,Trompt,FT-Transformer,TabTransformer,GraphSAGE-GNN,GANDALF,SELU-MLP,Tabular-ResNet,RFF-Kernel-Network,DANet,TabPFN-v2.6,LNN,VSN-TFT,TabNet,FM,FFM,DeepFM,DAE,MLP+embedding ·
  mod=agent,multi-view,embed,neg-weights ·
  topo=850 models built → 150 selected [90 tree + 60 NN claimed] → L1 extractors → L2 (5x5 nested OOF) → L3 `_stk` (5x5 nested OOF) → L4 cuML LogReg on L3+L2 OOF
  - Not a flat ensemble and not a single model: level-2 and level-3 models consume the *nested OOF predictions of the previous level* as inputs, so data flows forward through
    four training stages — a stack of stacks. The LLMs are the builder, not the topology; the submitted artifact is the cuML LogReg meta-learner.
  - The submitted prediction was the L4 logistic stack (published as the final notebook); the last two slots were the Ridge ensemble and the LogReg ensemble, and the LogReg
  stack achieved the best private LB (author comment).
  - In the published final notebook's input list, members with the `_stk` suffix are the level-3 models and the rest are level-2 (author, section 9); the level-4 LogReg consumes both. The source explicitly describes all four levels ("Our final solution is a 4 level stack").
- **Setup:** train.csv 600k synthetic rows + 7,032-row original IBM Telco data used as a feature source; 16 raw categorical columns; MonthlyCharges snaps map back to its 1,584
  unique original values; rows/cols of test not stated; submission-slot count not stated.
- **Features:** FE named the dominant performance driver; 12+ pipelines, per-technique model counts published:
  - Snap features (universal): `MC_snap` = nearest MonthlyCharges in original IBM data; `TC_snap` likewise; `MC_snap_diff = MonthlyCharges - MC_snap`; `TC_snap_diff` (encodes
    the generator's perturbation).
  - Digit/decimal extraction (~60 models): `frac = x - floor(x)`; `d1 = floor(frac*10)`; `d2 = floor(frac*100) % 10`; `frac100 = round(frac*100)`; `mod10 = floor(x)%10`;
    `mod100 = floor(x)%100`; fractional residuals from denominators 1/2, 1/4, 1/5, 1/10; is-round flags (`frac < 0.005`); digit pairs as categorical strings.
  - Nested leak-free target encoding (~90 models): inner 5-fold TE loop inside each outer fold, on all 16 categoricals, bigram/trigram combos, binned numerics, anchor keys,
    numeric × categorical snap products; TE statistics beyond mean: std, min, max, median, quantiles (5th, 10th, 45th, 55th, 90th, 95th).
  - Original IBM priors: churn probability per feature value computed once from the 7,032-row original data (zero leakage).
  - Arithmetic (~45): `TC_deviation = TotalCharges - tenure * MonthlyCharges` (called particularly powerful); `TC_snap_exp_dev = TC_snap - tenure*MC_snap`;
    `TC_per_month = TotalCharges/(tenure+1)`; `MC_to_TC_ratio = MonthlyCharges/(TotalCharges+1e-9)`.
  - Multi-scale binning (~52): quantile bins up to 5,000 (on MC these recover the 1,584 original unique values), fixed-width, log-scale, integer floor → categorical → TE.
  - Bigrams/trigrams (~37): e.g. `bi_Contract_Internet = Contract + "__" + InternetService`; top pairs Contract×InternetService, Contract×PaymentMethod,
    InternetService×PaymentMethod, nested TE on each.
  - Frequency/count encoding (~45): `freq = all_data[col].value_counts(normalize=True)`; count ratio = synthetic_count / original_count (generator oversampling per value).
  - Service counts (~30): `svc_yes = sum((df[c]=="Yes") for 7 service cols)`, `has_internet`, `has_phone`, per-service ISYES_/ISNO_/ISOTHER_ flags.
  - cKDTree original lookup (~7): nearest original customer in standardized (MC, TC, tenure), their churn label attached.
  - Radix interactions (~15): `radix = int(MC_snap*100) + cat_code*100_000` (single tree split ≈ joint numeric+categorical split).
  - Synthetic artifact detection: `intlike_count` (frac<0.001), quarterlike/halflike counts; TF-IDF character n-grams on the string forms of MC/TC; Benford's-Law deviation;
    drift ratios `log1p(train_freq/orig_freq)`.
  - Projection/manifold (~7): PCA (12 comps) + Gaussian Random Projection (12 comps) fit on original IBM data; cyclical tenure `sin/cos(tenure*2π/12)` and `*2π/24`.
  - Columns dropped: not stated.
- **Models:** 850 models built, 150 selected (published dataset contains 154 OOF/test prediction columns). Tree bloc (author says "90 of the 150"; the per-library counts sum to 85):
  - XGBoost 37 (incl. XGBRanker with `rank:pairwise` objective, Platt-scaled; `max_bin=16,000` for digit features; 3-seed rank blending), LightGBM 22 (baseline `num_leaves=63`;
    Optuna pick `num_leaves=77`, `learning_rate=0.00833`, `min_child_samples=56`), CatBoost 22 (native OTS on 16 categoricals; Optuna `random_strength=2.877`,
    `bagging_temperature=0.264`), YDF 2 (`max_depth=2`), cuML Random Forest 2 (only bagging member).
  - NN bloc (author says "60 of the 150"; the 25 families he enumerates sum to 100 members): Embedding MLP 10 (512→256→1, batch 256-8192, LR 2.5e-5-2e-3, label smoothing
    ε=0.02), Pair-Embedding MLP 2 (171 pair tables, dim ≤16), Enhanced MLP 4 (FREQ/RANK/log1p/SQRT/INV1P), RealMLP 9 (`RealMLP_TD_Classifier`, PLR, SiLU, `n_ens=8`),
    GraphSAGE 4 (k=8 KNN graph), FT-Transformer 4 (pytorch-frame, LinearPeriodicEncoder), TabTransformer 5, TabM 3 (`TabM_D_Classifier` tabm-mini-normal, k=32, best DL OOF
    0.918788), TabICL 3, GANDALF 2, SELU-MLP 2 (256→128→64→32 + 128-dim TF-IDF), Tabular ResNet 2 (4 residual blocks), RFF Kernel NN 3 (RFF dim 1,024 + 32 k-means prototypes),
    DAE 10 (latent 128→16 trained on original 7,032 rows; best variant dae-8907 OOF 0.918345), FFM 10 (~0.9159), Deep Residual MLP 4 (0.916376), FM 3 (k=32, 0.9155),
    DeepFM/DeepFFM 3 (0.9154-0.9158), LNN 3 (embedding variant 0.9151 vs plain 0.9128), VSN/TFT 4 (best 0.9141), TabNet 3 (~0.9122, self-supervised pretrain on original data),
    Trompt 3 (num_prompts=8, num_layers=4, 0.916291 with only 6 epochs, no TE/digit features), DANet 1, TabPFN v2.6 1 (0.9134 with 32 estimators×10k rows vs 0.9127 with
    64×5k), DAE transfer learning 2 (never exceeded 0.915).
  - Other hyperparameters, seeds per member beyond `SEED=42`, library versions: not stated.
- **CV:** 5-fold `StratifiedKFold`, `SEED=42`, for all models; nested 5x5 OOF between stack levels.
  - Final stack OOF AUC 0.91985; the author's private/public LB scores are never published in the writeup.
  - Author comment: ensembling his solution with 3rd place and 7th place solutions moved private LB only `+0.00001` — he reads this as being at the ceiling.
- **Ensembling:** all 150 base OOF columns → Nvidia cuML L2-penalized Logistic Regression (logit stacking) trained on labels; L2 penalty stops one model dominating correlated
  streams; penalty strength not stated.
  - Second-layer stacking: `_stk` members consume earlier models' OOF as input features (raw features → stacked models → final logit meta).
  - Greedy forward selection (hill climbing) on OOF AUC with negative weights allowed; but final two submissions were the Ridge and LogReg ensembles — both had better CV than
  hill climbing; author's general observation: "Log Reg or Ridge performs better than HC".
  - LogReg + greedy forward selection over the 25 DL families: the first 13 (through RFF Kernel NN) were selected, the last 12 (DAE onward, incl. FFM, TabNet, Trompt,
    TabPFN) were not; all tree families were selected.
- **Post-processing:** none stated (XGBRanker outputs Platt-scaled to [0,1] as part of that member).
- **Gains:** (+0.00001 private LB) blending 1st+3rd+7th solutions together — evidence the whole board was at ceiling.
- Snap features + decimal digit extraction: named "the two most impactful techniques", but no isolated delta published (unquantified).
- (+0.0007) TabPFN config 64×5k → 32×10k rows (0.9127 → 0.9134).
- (+0.0023) LNN plain → embedding variant (0.9128 → 0.9151).
- Best single model published: TabM OOF 0.918788; best XGB/LGB/CAT public-reference singles ~0.919; final stack OOF 0.91985.
- ~50% of the 25 DL/FE approaches were invented by the LLMs on prompt "make a model that is not currently in my ensemble" (author comment).
- **Failed:** the last 12 of 25 DL families were rejected by greedy LogReg selection (enumeration order: DAE as a *final model*, FFM, FM, DeepFM, LNN, VSN, TabNet, Trompt,
  DANet, TabPFN v2.6, DAE transfer, deep residual MLP) — though DAE features still fed XGBoost at level 1.
- TabPFN v2.6 structurally capped: 475k train rows force 5k-10k subsampling per estimator, "capping performance well below full-dataset models".
- DAE transfer learning: pretraining advantage never pushed supervised phase past 0.915.
- Hill climbing lost to Ridge/LogReg on CV and was not submitted.
